# 当前复盘流程设计说明

本文描述当前项目已经落地的完整复盘设计，重点说明**每日复盘、实际操作评价、周策略生成、形态/趋势定义、输出位置和失败恢复**之间的关系。

当前推荐日常使用本地规则引擎：

```bash
.venv/bin/python -m review_workflow start --date YYYY-MM-DD --provider local --execute
```

该模式不调用 Gemini / 智谱，复盘结论完全来自公开行情数据、持仓文件和本地规则。

## 1. 设计目标

当前复盘流程围绕六个目标设计：

1. **每日可执行**：交易日收盘后输入当前持仓和当日操作，自动生成个股复盘与组合摘要。
2. **周策略连续**：周五或周末提前生成下一周策略；周内每天读取同一份策略并追加执行回顾。
3. **操作可评价**：自动识别当日买入/卖出记录，评价成交位置、执行纪律和后续动作。
4. **规则可解释**：形态、趋势、左右侧买入、止损线均输出明确定义和触发条件。
5. **数据可审计**：截图、元数据、个股 sidecar、周策略 JSON、最终 Markdown 全部落盘。
6. **失败可恢复**：截图、分析、摘要、渲染分阶段保存；失败后可以从断点继续。

## 2. 总体节奏

### 2.1 交易日收盘后：每日复盘

适用时间：周一至周五，建议收盘后执行。

流程：

```text
my_stock.txt
  -> 初始化当日工作流
  -> 逐只股票截图 / 复用截图
  -> 逐只股票生成本地复盘
  -> 读取或生成本周策略
  -> 追加今日策略执行回顾
  -> 生成组合摘要
  -> 输出当日最终复盘文档
```

每日复盘会回答：

- 今日持仓盈亏多少？
- 当前形态是什么？如何定义？
- 当前趋势是什么？如何定义？
- 今日实际买入/卖出执行质量如何？
- 是否触发支撑、压力、突破或止损条件？
- 后续应该继续执行、减仓、等待右侧，还是修复买回？

### 2.2 周五或周末：提前生成下一周策略

适用时间：

- 周五收盘后；
- 周六；
- 周日。

系统会把当前日期映射到下一周：

```text
2026-09-18 周五 -> 2026-W39
2026-09-19 周六 -> 2026-W39
2026-09-20 周日 -> 2026-W39
```

周末运行时，不会把周六或周日当成交易日；行情和指标使用最近一个交易日，通常是周五。

周五或周末会额外截取：

```text
04_daily_kline.png
04_weekly_kline.png
```

并复制到下一周策略目录：

```text
screenshots/weekly/YYYY-Www/charts/股票名称_股票代码_daily_kline.png
screenshots/weekly/YYYY-Www/charts/股票名称_股票代码_weekly_kline.png
```

### 2.3 下一周周一至周五：读取既有周策略

周内每日复盘时会读取当前 ISO 周的策略单：

```text
screenshots/weekly/YYYY-Www/YYYY-Www_交易策略单.json
screenshots/weekly/YYYY-Www/YYYY-Www_交易策略单.md
```

然后追加当天的：

- 是否触发支撑/压力/突破/止损；
- 当日实际操作执行质量；
- 是否继续执行原策略；
- 是否因持仓变化自动升级策略版本。

### 2.4 本地模式与 AI 模式

当前日常流程推荐 `provider=local`：

- 不调用 Gemini / 智谱；
- 不消耗模型 API Key；
- 使用公开行情、公告、财报、F10 与本地规则生成结论；
- 周策略、形态定义、趋势定义和止损线均由确定性规则计算。

项目仍保留 AI 模式：

- `provider=gemini` 或 `provider=zhipu`；
- 截图和持仓信息会发送给所选模型；
- 输出 `gemini当日复盘.md` 或 `zhipu当日复盘.md`；
- 适合作为补充视角，不作为当前日常默认流程。

## 3. 持仓与当日操作输入

持仓文件为 `my_stock.txt`。

### 3.1 股票行

格式：

```text
股票名称,综合成本,总持股数,计划持有时间
```

示例：

```text
贵州茅台,1500,100,6个月
平安银行,10.50,2000,1年
```

重要口径：

- 股票行代表**当前真实总持仓**；
- 成本是**当前综合成本**；
- 如果当天已经买入或卖出，股票行应先更新为操作后的持仓和综合成本；
- 程序不会用操作行自动反推股票行。

### 3.2 当日操作行

操作行必须紧跟对应股票行，用于评价当天实际执行。

买入：

```text
34.80,买入100
```

卖出：

```text
34.80,卖出100
```

也兼容：

```text
34.80,买100
34.80,卖100
34.80,买入,100
```

操作行只用于当日执行评价，不会自动修改股票行的成本和股数。

可用范围说明：

- 操作行当前只支持 `my_stock.txt` 文件输入，适合 CLI / 本地日常流程；
- 前端和 HTTP API 当前只提交股票名称、成本、股数、计划周期，不提交操作行；
- 因此前端 / API 创建的任务会显示“未记录实际操作”；
- 需要评价当日买卖时，请先更新 `my_stock.txt`，再用 CLI 执行本地复盘。

## 4. 工作流阶段

整体工作流按原子步骤执行：

```text
initialize
  -> stock[1] capture -> stock[1] analyze
  -> stock[2] capture -> stock[2] analyze
  -> ...
  -> summary
  -> render final document
```

`workflow_state.stage` 中的全局阶段只有 `capture`、`analyze`、`summary`、`render`。
周策略不是独立状态机阶段；在 `provider=local` 时，它作为 summary 阶段中的
本地规则子步骤执行。

### 4.1 initialize

做三件事：

1. 解析复盘日期；
2. 读取 `my_stock.txt` 或前端提交的持仓；
3. 创建当日 `workflow_state.json`。

状态文件路径：

```text
screenshots/YYYY/MM/DD/workflow_state.json
```

### 4.2 capture

每只股票独立执行截图阶段。

常规截图：

```text
01_trading_data.png
02_intraday_chart.png
03_bid_ask_5.png
04_daily_kline.png
```

同时会识别并抓取板块截图，写入：

```text
boards_metadata.json
```

周五或周末额外抓取：

```text
04_weekly_kline.png
```

截图完成后写入：

```text
metadata.json
```

其中记录：

- 用户输入；
- 解析后的股票名称、代码、市场；
- Eastmoney `quote_id`；
- 截图清单；
- 复盘日期；
- 当日持仓。

### 4.3 analyze

`provider=local` 时，不调用模型，直接收集公开数据并生成规则化复盘。

主要数据源：

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| 日线 OHLCV | 搜狐历史行情 | 均线、RSI、量能、支撑压力、周线聚合 |
| 当日快照 | 东方财富公开接口 | 搜狐日线延迟时的同日兜底 |
| 估值与板块 | 东方财富公开接口 | 市值、PE/PB、板块表现 |
| 财报 | 东方财富公开接口 | 收入、利润、毛利率、现金流 |
| 公告与新闻 | 东方财富公开接口 | 近期事件线索 |
| F10 股东人数 | 东方财富 F10 | 最新股东人数 |
| 融资融券余额 | 东方财富数据中心 | 最新两融余额 |

F10 当前只保留两项：

1. 最新股东人数；
2. 最新融资融券余额。

公司简介、主营构成、地区收入、概念、实际控制人、前五大流通股东等不再输出。

### 4.4 weekly strategy：本地摘要子步骤

仅在 `provider=local` 时执行，发生在本地组合摘要前。

如果是周五或周末，生成下一周策略；如果是周内，读取当前周策略。

注意：

- 该步骤没有独立的 `workflow_state.stage` 值；
- 失败或重试粒度归属于 `summary` 阶段；
- AI 模式不会生成本地周策略。

### 4.5 portfolio summary

汇总所有成功个股：

- 组合市值；
- 今日盈亏；
- 浮动盈亏；
- 单票权重；
- 弱趋势持仓；
- 高换手持仓；
- 指数对照；
- 组合级风险结论。

### 4.6 render

输出最终文档：

```text
screenshots/YYYY/MM/DD/YYYYMMDD_持股个股复盘.md
```

即使部分或全部个股失败，也会生成可审计的失败报告版最终文档。

## 5. 每日个股复盘内容

每只股票生成：

```text
screenshots/YYYY/MM/DD/股票名称_股票代码/local当日复盘.md
screenshots/YYYY/MM/DD/股票名称_股票代码/local_review_data.json
```

Markdown 主要包含：

1. 数据与结论；
2. 今日实际操作复盘；
3. 当日交易数据；
4. 技术面与量价；
5. 当前形态、趋势定义、趋势强度与趋势变化；
6. 支撑/压力区域（区域、强度、形成原因、突破/跌破确认）；
7. 板块表现；
8. F10 关键数据；
9. 财报与公告；
10. 公开新闻线索；
11. 关键价位与预案（按支撑区/压力区分档）；
12. 数据来源说明。

### 5.1 持仓盈亏

计算：

- 当前市值；
- 相对综合成本的浮动盈亏；
- 今日持仓盈亏；
- 当日买入/卖出后的实际盈亏口径；
- 单票在组合中的权重。

### 5.2 技术指标

日线指标：

- MA5 / MA10 / MA20 / MA60；
- 5 日均量 / 10 日均量；
- 量能倍数；
- RSI6 / RSI12 / RSI24。

### 5.3 当前形态定义

系统基于当前 K 线和前一根 K 线识别形态。

当前支持：

| 形态 | 定义要点 |
| --- | --- |
| 阳线反包 | 当前阳线实体覆盖前一根阴线实体至少 80%，并重新站上前阴线开盘价 |
| 阴线反包 | 当前阴线实体覆盖前一根阳线实体至少 80%，并跌破前阳线开盘价 |
| 长下影线 | 下影线至少为实体 2 倍，且至少为上影线 1.5 倍 |
| 长上影线 | 上影线至少为实体 2 倍，且至少为下影线 1.5 倍 |
| 十字星 | 实体不超过当期振幅 15% |
| 放量阳线 | 阳线且成交量达到 5 期均量 1.2 倍以上 |
| 放量阴线 | 阴线且成交量达到 5 期均量 1.2 倍以上 |
| 普通阳线 / 普通阴线 | 未触发特殊形态条件的普通 K 线 |
| 形态待核实 | OHLC 缺失或数据不合理 |

日线使用“当日 / 次日 / 5 日均量”口径。

周线使用“当周 / 下一周 / 5 周均量”口径。

### 5.4 当前趋势定义

趋势由收盘价与 MA5 / MA10 / MA20 的关系决定，并结合 RSI 状态。

| 趋势 | 定义 |
| --- | --- |
| 强上升趋势 | 收盘价站上 MA5/MA10/MA20，且 MA5 > MA10 > MA20 |
| 回升趋势 | 收盘价站上 MA5/MA10/MA20，但均线尚未多头排列 |
| 震荡整理 | 收盘价与三条均线位置交错 |
| 弱势破位 | 收盘价跌破 MA5/MA10/MA20，但均线尚未空头排列 |
| 空头下跌趋势 | 收盘价低于 MA5/MA10/MA20，且 MA5 < MA10 < MA20 |
| 趋势待核实 | 收盘价或均线数据不足 |

日线趋势使用 RSI6。

周线趋势使用周线 RSI12。

### 5.5 趋势强度与趋势变化

在原有「趋势状态」之外，系统再输出两个独立维度：

```text
趋势状态：强上升趋势
趋势强度：强（强度评分 78/100）
趋势变化：↓ 减弱
趋势依据：...
趋势解读：...
```

规则：

1. **趋势状态**：仍由 5.4 的原有规则判断，本次没有修改；
2. **趋势强度**：把「均线排列、均线斜率、价格距离 MA20、RSI」综合成 0~100 分，再映射为 `弱 / 中 / 强`；
3. **趋势变化**：比较当前窗口与 5 个交易日（周线为 4 周）之前的窗口，观察
   MA5/MA10/MA20 斜率变化、价格与 MA20 距离变化、RSI 变化与成交量变化，
   再归入 `加强 / 稳定 / 减弱 / 反转`。

关键约束：

- 「强上升趋势」不等于「未来继续加速」，因此状态和变化必须分开看；
- **趋势变化减弱时不会把趋势状态直接改成下跌**；
- 只有中期均线（MA20）斜率由升转降（或由降转升）才标记为 `反转`；
- RSI 只作为强度与变化的辅助输入，不能单独决定趋势状态；
- 价格明显偏离 MA20 时区分「短期过热」（在上方）与「短期超跌」（在下方），
  两者都不作为买入理由。

### 5.6 支撑/压力区域

原来的「支撑1/支撑2/压力1/压力2」升级为「支撑区 / 压力区」，每个区域包含：

```json
{
  "zone_type": "RESISTANCE",
  "zone_low": 36.3,
  "zone_high": 36.8,
  "strength": 4,
  "reasons": ["前期高点", "60日高点", "前期成交密集区域"],
  "breakout_confirmation": {
    "close_above": 36.8,
    "volume_ratio_min": 1.2,
    "additional_conditions": ["收盘位于 MA5/MA10 上方", "周线守住 5 周线或 10 周线"]
  }
}
```

区域来源（全部来自已有行情数据，不引入新指标）：

| 来源 | 说明 |
| --- | --- |
| 前高 / 前低 | 局部极值（左右各 2 根 K 线确认） |
| 20 / 60 / 120 日高低点 | 中期、长期关键价位 |
| 多次价格反应 | 同一价格附近反复冲高回落或探底回升 |
| 成交密集区域 | 用已有成交量做价格分箱，不做复杂筹码模型 |
| 均线附近 | MA5 / MA10 / MA20 / MA60 |

合并与强度规则：

1. 价格非常接近的多个来源会合并为同一个区域，同时合并形成原因，
   避免出现「压力 36.5 / 36.6 / 36.7」这种没有意义的重复区域；
2. 区域强度为 1~5 分，来源包括：来源类型、历史反应次数、价格反应幅度、
   时间跨度（60/120 日）、是否与均线重合；
3. **均线只作为形成原因之一**：只有均线作为来源时强度最高 2 分，
   不会把 MA20 直接当成支撑位；
4. 当日高/低点只在结构性区域不足两个时用于补足，避免短期噪音挤占结构区域；
5. 来源按「相对当日收盘价的位置」分侧：价位在收盘价上方记为压力，
   下方记为支撑，因此前高被有效突破后转为支撑、前低被跌破后转为压力；
   区域再做一次裁剪，保证支撑区上沿不超过收盘价、压力区下沿不低于收盘价，
   两侧不会互相重叠。

有效突破条件：

```text
收盘 > 压力区上沿
且成交量 ≥ 5 日均量 1.2 倍（沿用现有右侧突破规则）
且收盘位于日线 MA5 / MA10 上方
且周线守住 5 周线或 10 周线
```

本次只把「突破压力位」升级为「有效突破整个压力区」，没有新增买入条件。

### 5.7 实际操作评价

如果 `my_stock.txt` 中有当日操作行，系统会检查：

- 成交价是否在当日最高价与最低价之间；
- 成交价相对当日均价的位置；
- 买入是否落在支撑区内，或落在压力区内（追高风险）；
- 卖出是否落在压力区内，或落在支撑区内（恐慌卖出）；
- 买后是否处于正确状态；
- 卖出后是否过早；
- 操作价是否低于周策略止损线。

输出包括：

- 执行评价；
- 纪律评价；
- 相对收盘结果；
- 后续操作建议。

## 6. 周策略设计

### 6.1 生成时机

| 运行日 | 策略目标 |
| --- | --- |
| 周五 | 下一周 |
| 周六 | 下一周 |
| 周日 | 下一周 |
| 周一至周四 | 当前周 |

如果周一没有找到提前生成的策略，会按当日持仓补建，并在更新记录中说明。

### 6.2 周线数据

周线由日线聚合而来：

- 周开盘：本周第一根日线开盘；
- 周收盘：本周最后一根日线收盘；
- 周最高：本周所有日线最高价最大值；
- 周最低：本周所有日线最低价最小值；
- 周成交量：本周日线成交量求和。

再计算：

- 周 MA5；
- 周 MA10；
- 周 MA20；
- 周线 RSI12；
- 5 周均量。

### 6.3 策略文件结构

每只股票在周策略 JSON 中包含：

```text
股票与代码
基准成本
股数
计划周期
基准收盘价
持仓权重
支撑区1 / 支撑区2（区域、强度、原因、跌破确认）
压力区1 / 压力区2（区域、强度、原因、突破确认）
核心策略
建议减仓数量
日线指标快照
周线指标快照
日线形态
日线趋势（状态 + 强度 + 变化）
周线形态
周线趋势（状态 + 强度 + 变化）
左侧买入计划
右侧突破计划
止损计划
```

为兼容旧版本，JSON 中同时保留 `support_1 / support_2 / pressure_1 / pressure_2` 四个价格点字段。

### 6.4 左侧买入

左侧买入区：

```text
支撑区2 下沿 ~ 支撑区1 上沿
```

启用前提：

- 周线收盘价不低于周 MA10；
- 支撑区数据有效。

触发条件（本次没有改动）：

- 回踩支撑区分批承接；
- 量能不高于 5 日均量 80%；
- RSI6 ≤ 40；
- 周线收盘不破 10 周线。

默认建议数量：

```text
当前持股数的 10%，按 A 股整数取整
```

如果周线收盘已跌破 10 周线，左侧买入会停用。

### 6.5 右侧买入

正常趋势下触发条件：

```text
有效突破压力区1（收盘 > 压力区1 上沿）
```

弱势股触发条件：

```text
有效突破压力区2（收盘 > 压力区2 上沿）
```

其余条件（本次没有改动）：

- 收盘站上触发价（即区域上沿）；
- 日收盘位于 MA5 / MA10 上方；
- 成交量不低于 5 日均量 1.2 倍；
- 周线需守住 5 周线或 10 周线；
- 弱势股必须先收复 MA5。

默认建议数量：

```text
当前持股数的 15%，按 A 股整数取整
```

### 6.6 止损线

止损线结合三类约束：

1. 第二支撑下方 2%；
2. 周 MA10 下方 2%；
3. 单周最大 8% 风险预算。

执行规则：

```text
盘中跌破或等于止损线：先降半仓
收盘确认跌破或等于止损线：执行剩余减仓或清仓
```

每日复盘时：

- 如果收盘价低于或等于止损线，标记“已触发止损线”；
- 如果当日实际买入价低于或等于止损线，标记“与周策略风控冲突”。

### 6.7 策略触发记录与版本更新

以下情况会自动更新策略版本：

1. 持仓成本变化；
2. 持股数量变化；
3. 新增持仓；
4. 移除持仓；
5. 旧策略格式需要升级。

支撑、压力、突破、止损和操作质量触发条件的处理方式不同：

- 系统会把触发原因写入当日执行回顾；
- 默认决策仍显示“继续执行”；
- 是否修改策略由人工确认；
- 只有持仓变化或旧格式升级才自动生成新版本。

旧版本信息保留在：

```text
change_log
```

当前策略格式为 `signal_schema v4`，旧策略读取时会自动补充：

- 日线形态；
- 日线趋势（状态 + 强度 + 变化）；
- 周线形态；
- 周线趋势（状态 + 强度 + 变化）；
- 支撑/压力区域（区域、强度、原因、突破确认）；
- 左右侧买入；
- 止损线。

升级方式为向后兼容：持仓未变化时按最新字段重建策略并递增 `version`，
原因写入 `change_log`；无法升级的旧策略仍会被正常读取。

## 8. 日期与数据口径

### 8.1 交易日复盘

复盘日必须是交易日，或者公开数据能返回该日期的行情。

如果搜狐日线延迟，系统会用东方财富同日快照兜底；东方财富 push2 行情集群
整体限流时，再用腾讯行情（`qt.gtimg.cn`）补当日快照与估值（市值、PE、PB、
换手率、涨跌），量比腾讯不提供、记为待核实。

### 8.2 周末复盘

周六或周日运行时：

- 不会把周末当成交易日；
- 使用最近一个交易日，通常是周五；
- 周线以最近交易周为基准；
- 策略目标仍是下一周。

### 8.3 历史复盘

估值与板块实时快照会校验日期。补跑历史日期时，如果快照日期不匹配，相关字段会标记为“待核实”，不会把最新数据误写成历史数据。

F10 股东人数与融资融券余额均按复盘日截止时间过滤。

## 9. 失败恢复

查看状态：

```bash
.venv/bin/python -m review_workflow status --date YYYY-MM-DD
```

从断点继续：

```bash
.venv/bin/python -m review_workflow resume --date YYYY-MM-DD --execute
```

复用已有截图：

```bash
.venv/bin/python -m review_workflow resume \
  --date YYYY-MM-DD \
  --skip-capture \
  --execute
```

恢复规则：

| 阶段 | 恢复行为 |
| --- | --- |
| capture_failed | 重新截图 |
| analysis_failed | 保留截图，重试分析 |
| analyzed | 复用已有个股复盘 |
| summary/render 失败 | 复用成功个股，重试摘要或渲染 |

注意：

`--skip-capture` 会严格跳过所有截图，也不会补抓周 K。如果需要补周 K，请去掉该参数运行。

## 10. 推荐日常操作顺序

### 10.1 交易日收盘后

1. 更新 `my_stock.txt` 中的总持仓和综合成本；
2. 在对应股票下添加当日操作行；
3. 执行本地复盘；
4. 查看最终文档；
5. 检查是否触发周策略止损或关键价位。

### 10.2 周五收盘后或周末

1. 更新 `my_stock.txt`；
2. 执行本地复盘；
3. 确认系统已生成下一周策略；
4. 检查日线/周线截图；
5. 检查左右侧买入条件是否合理；
6. 下一周按该策略单执行。

### 10.3 下一周每日

1. 每天正常运行复盘；
2. 系统自动读取本周策略；
3. 当日操作会写入每日执行回顾；
4. 触发止损或关键价位时，系统记录原因，人工决定是否修改策略；
5. 持仓变化或旧格式升级时，系统自动更新策略版本。
